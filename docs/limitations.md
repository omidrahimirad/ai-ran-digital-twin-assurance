# Limitations

This prototype evaluates software behavior with synthetic inputs; it does not provide
evidence of network performance.

## Telecom and modeling limits

- No RF propagation, fading, link budget, beamforming, antenna pattern, scheduler,
  protocol stack, UE, bearer, packet, alarm, or vendor PM-counter model exists.
- Throughput, PRB, SINR, BLER, RRC, mobility, drop, latency, and availability equations
  are deliberately simplified and are not standards-derived.
- Faults are single, deterministic, and closed-set. Concurrent, intermittent, gradual,
  previously unseen, missing-data, and distribution-shift cases are absent.
- A label such as `missing_neighbor` identifies what the injector did; KPI evidence alone
  cannot prove that configuration cause. The RCA therefore retains ambiguity.
- `NetworkTwin` is copied state. Its simulator uses fixed bounded response equations and
  does not estimate causal or RF effects.

## ML and evaluation limits

- The only ML model is an Isolation Forest fitted to a clean synthetic generator baseline.
- Training/evaluation seed separation does not provide external-domain validation.
- Thresholds, rule weights, action effects, and confidence values are uncalibrated.
- The 100% precision and zero observed false-alarm rate apply only to normal intervals
  generated by the same closed-set family; they should not be expected on field data.
- Recall is 53.99%, episode detection is 79.17%, and RCA accuracy on diagnosed episodes
  is 52.63% in the committed run. RCA accuracy excludes undetected episodes.
- Immediate deterministic injection can yield zero-minute delay on detected episodes;
  that is not a real fault-detection latency claim.
- There is no commercial, laboratory, field, standards, or independently curated dataset.
- The API smoke uses an in-process client and reports no timing result.

## Safety and operational limits

- There is no live ingestion, persistence, identity, authorization, rate limiting, audit
  backend, high availability, disaster recovery, or multi-user isolation.
- The demo API must not be exposed to an untrusted network. Local startup binds loopback;
  Docker intentionally publishes ports for local demonstration.
- Guardrails cover the modeled KPI/action contract only. They are not an operator safety
  policy, formal verification, or protection against all unsafe network changes.
- No action can be executed because no southbound client exists. Human approval is not
  implemented as a persisted workflow.

## Standards and claims

The implementation does not claim 6G, IMT-2030, or O-RAN compliance; standards
conformance; production readiness; operator validation; autonomous operation; a real
RIC; a high-fidelity digital twin; or a real operator network. It does not implement
E2SM-KPM, E2SM-RC, O1, A1, E2, NTN, ISAC, or energy optimization.
